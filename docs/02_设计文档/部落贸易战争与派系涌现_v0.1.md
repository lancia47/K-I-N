## 0. 本轮决策与适用边界

本轮明确：玩家能够参与、领导、影响部落，也可能因持续分歧失去领导权；在角色仍存活且基础游戏允许行动的情况下，失位不等于结束游戏。该结果允许发生，不由导演系统强制触发。

本规格补充贸易、共同决定、有限冲突、派系和领导权的规则。现有阶段 0–7 的执行顺序、代码保护边界、资产准入规则保持不变。新扩展排在既有生存、生态、社会因果验收之后。

现行设计口径为“主设计 v0.5＋本扩展 v0.1”。涉及本文主题的细化以本规格为准；原生存生态基线仍决定当前开发优先级。旧版本原文保留，不静默重写历史。

本轮只建立文档，未检查本地脏文件，未修改 `proto_h01/`、`godot_ai`、`tools`、存档或模型接入代码。数值规则一律作为 PROVISIONAL 候选，不得在实际工程中静默替换现有参数。

## 1. 要做出的游戏循环

```text
个体生活与生产
→ 看见需求或交换机会
→ 提议与商议
→ 获得有限授权、资源和参与者
→ 交易 / 护送 / 搜救 / 有限冲突
→ 真实交付、损失或伤亡
→ 不同的人获得不同信息
→ 信任、义务、怨恨、合作预期变化
→ 重新分工、调整授权或形成派系
→ 改变下一轮生活与对外交往
```

贸易、战争、派系是这条循环的不同表现，不是三套互不相干的面板。系统必须允许没有玩家参与的 NPC—NPC 交易、协商和集体行动。

涌现不等于没有规则。规则定义动作、成本和后果；具体参与者、时间、原因和结果不预先指定。日志负责记录已经发生的事，不负责下发“请发生一场战争”。

## 2. 社会对象必须拆开

| 对象 | 定义 | 不应自动等同于 |
|---|---|---|
| 个人 | 有稳定 ID、经历、财物和行动能力的主体 | 其职位或所属团体 |
| 营地 | 居住、储存、生产发生的地点 | 一个统一意志 |
| 家族 | 亲缘或被承认的家族身份网络 | 所有成员立场一致 |
| 部落 | 共同承担部分事务的持续组织 | 一个营地或一个姓氏 |
| 派系 | 围绕某种利益或主张反复协调的群体 | 所有不满者的自动集合 |
| 联盟 | 不同组织围绕具体事务形成的合作约定 | 永久合并、全事务同盟 |
| 职位 | 在特定范围内协调或使用公共资源的授权 | 人格、全部财产和永久服从 |

个人可以有多种身份。跨营地的家族、同部落内的多个派系、不同部落之间的熟人，都应在数据表达上成立。第一版不实现所有组合，但不能把它们压成唯一 `faction_id`。

名称只是可识别线索。真实成员身份、对外自称身份、观察者相信的身份分别保存。同姓不自动共享思想；陌生 NPC 不因数据库中存在某组织就知道它。

## 3. 组织可以被提议，也必须有人实行

玩家或 NPC 可以命名团体、提出规则和邀请成员。这是合法社会行动，不禁止“建立团体”按钮。

团体的执行能力来自成员承认、承担义务、共享资源或反复协调，而非按钮自动附送。外界不知道的秘密团体也可以存在；外部声誉影响别人如何回应，不是存在与否的必要条件。

区分：

- **存在**：成员之间已建立有效的组织约定。
- **运作**：仍有人承担事务、兑现承诺、控制相应资源。
- **被识别**：哪些外部主体知道这个组织并持有什么判断。

三者可不同步。组织休眠或解散后，成员历史、未结债务、伤亡和旧称谓仍保留。

## 4. 地理与资源：创造交换理由，不强迫唯一答案

最小世界用河边营地和山边营地测试。资源差异先使用现有资源目录中已实现的食物、药材或工具材料；示例中的鱼、药材不是对现有代码状态的确认。

双方应有基本生存办法，交换带来节省时间、降低风险或改善照料的收益。避免把全部食物放一边、全部生存必需品放另一边，导致“不交易就必死”。

收益来自具体条件：产出效率、现有库存、劳动时间、道路风险、运输负重、已有需求和承诺。第一版不做完整货币市场、全局均衡价格或复杂生产科技树。

部落只依据成员观察、运输回报和传来的报价了解对方。缺少药材不自动知道远处哪个仓库有药，也不自动产生最短安全路径。

## 5. 贸易：谁拿什么，谁送，谁承担风险

### 5.1 提议与权限

交易提议包含双方、标的、数量、交付地点、约定时间、交付先后、损失承担、是否允许部分交付以及担保范围。第一版默认不允许部分交付，除非双方明确接受。

私人交易只能使用本人有权处分的物资。代表部落交易需要在授权范围内使用公共仓库，不能把每个成员的私人库存当作集体资产。

对方可接受、拒绝、反报价或请求担保。拒绝不必损害关系；违反已经接受的承诺与拒绝新提议是不同事件。

### 5.2 交付与真实运输

```text
提议 → 条件协商 → 接受并检查授权 → 物资预留
→ 找到运输者 → 出发 → 到达 → 检查货物 → 交付 → 结算
```

物资预留不是物资消失。运输者只是保管人时，不能默认取得所有权。交付后按协议转移所有权；运输者受伤或死亡，货物保留在其实际位置或被实际接管，不在目标仓库自动补齐。

第一种实现采用双方货物在同一会合点交换，成功结算时原子更新两边库存。后续才做先送后付等信用交易；远程两地不允许假装同时原子交换。

### 5.3 延误与归责

超过约定时间，系统记录“未按时交付”。它不证明欺骗、敌对或故意违约。收货人可形成不同判断，并要求解释、搜救、返还或停止后续交易。

运输原因分层：实际野兽袭击属于事实；收货人知道货物未到属于感知；认为卖方私吞属于信念。后续证据能够改变判断，但不回写已经发生的事。

### 5.4 贸易的内部后果

交易会改变谁获益、谁劳动、谁承担风险。运货者可能要求补偿，伤员家庭可能支持稳定药材供应，其他人可能担心本地口粮。

这些差异通过个人需求、实际分配和经历进入下一次判断，不给整个部落统一增加一个“贸易好感度”。交易网络可以跨越家族和派系，也可以在外交紧张时通过个人关系继续存在。

## 6. 共同决定：合作必须可执行，自主性不等于处处拒绝

### 6.1 共同任务的最小合同

群体任务要明确目标、资源预算、可接受风险、分工、报酬或份额、开始与结束条件，以及退出方式。NPC 可以接受、拒绝、协商或因更紧迫的需求请求延期。

一旦接受且条件未明显变化，NPC 持续执行，不每个 tick 重掷是否反悔。伤势、任务超出约定、重大威胁或家庭急事可以触发重新判断。

“同意护送”不等于“同意进攻对方营地”；任务升级必须重新征求或依据既定授权处理。

### 6.2 常规事务与重大事务

| 情境 | 默认处理 |
|---|---|
| 约定范围内的日常运输、采集 | 按长期分工执行，避免频繁弹窗 |
| 预算或风险明显增加 | 提出新的任务条款，参与者重新回应 |
| 使用公共储备、改变主要分配规则 | 按组织授权规则商议 |
| 报复、危险远行或更换协调者 | 明确提议、支持范围与执行者 |

NPC 主动解决常规事务。玩家只收到与自身权限、承诺或近期危险有关的重要提醒。玩家可以委托，不需要扮演所有人的秘书。

### 6.3 第一个治理约定

为便于测试，两个营地先使用“有限协调者＋重大事项成员确认”的规则档案。它是虚构原型约定，不代表现实部落普遍如此。

协调者可安排已同意的日常任务、在限额内使用指定公共物资。超范围提议需要有资格的成员实际收到消息并表达支持；沉默不是同意。投票或支持记录不替代参加行动的承诺。

具体资格、门槛和时限由版本化的组织规则表达。技术规格给出一个 PROVISIONAL 测试档案；后续可以增加其他治理方式，但第一版不做完整制度编辑器。

## 7. 从事故到战争：中间必须有行动

### 7.1 不把敌对写成全图开关

```text
实际损失
→ 目击或传闻
→ 提出指控
→ 求证、返还或赔偿要求
→ 获得支持与参与者
→ 一次有限集体行动
→ 新后果
→ 再次判断是否继续
```

各环节都可停止、跳转或失败。有人认为应报复，其他人仍可选择继续交易、保持中立或离开。

私人冲突、未经授权的袭击、组织授权的行动要分别记录。受害者是否把个人行为归因于全体，取决于其认知和经历，不由系统统一决定。

### 7.2 第一版的战争范围

先支持有限武装行动：保护运输队、夺回具体货物、驱离某个争议地点的行动者。必须复用已通过验收的伤害、伤势、移动和资源规则。

每次行动具备提出者、授权依据、真实参与者、具体目标、资源预算、补给、可观察路线及停止条件。没有人愿意参加或没有物资，行动不能由一条旁白执行成功。

目标达成、参与者撤回、无法继续补给、损失达到事前约定或双方达成停战，都可结束行动。战斗胜利不自动吞并对方部落，击败首领不自动夺得全部仓库和成员。

大规模军队、攻城、占领治理和完整俘虏系统属于远期扩展，不是本轮必做项。持续战争是多次集体敌对行动及其安排形成的状态；一次争斗不自动被命名为部落战争。

### 7.3 修复与降温

第一版必须给出与冲突同等清晰的和平动作：解释、返还、补偿、重新担保、暂停后再恢复交易、共同处理道路危险。

停战约定只绑定有权代表的人及接受约定的组织范围，不神奇控制所有独立行动者。未经授权继续袭击的人会留下新的责任事件。

修复保留旧记忆，也允许新的履约证据改善合作。怨恨不能被一条“和解成功”全部清零，更不能成为永远只能恶化的变量。

## 8. 派系：反复协调比共享情绪更重要

### 8.1 形成条件

派系围绕可执行主张形成，例如继续贸易、优先保留本地口粮、支持搜救、限制某次报复、重新分配运输收益。

先有实际行为：多次共同提议、投放资源、承担任务、相互担保、支持同一协调者。系统可以识别这种模式，但识别标签本身不增加资源、忠诚或控制力。

共同愤怒、姓氏相同或关系分数接近，不足以自动产生派系。一次临时合作也不立即成为永久阵营。

### 8.2 生命周期

```text
议题上的暂时结伴
→ 反复协调
→ 出现共同承诺或资源安排
→ 成员承认的非正式派系
→ 可选择命名、推举代表或公开立场
```

派系可以休眠、和平解散、重新组合或从部落退出。外部世界是否知道它是单独的认知问题。

首轮实现以明确成员接受和可追溯合作记录建立组织对象。图聚类只作为调试观察或发现候选，不用“算法划了一个簇”来强迫成员加入。

### 8.3 分裂必须有实际过程

成员提出离开、带走有权支配的财物、协商公共物资份额、前往已有可达地点并建立新安排。不能低于某个好感度就复制出一个新营地及全部物资。

派系不必分裂；达成新的分配或授权安排，也可以继续在同一部落内生活。将来跨部落派系和联盟可复用同一成员及承诺结构，不再新增互不兼容的阵营系统。

## 9. 领导权：正式职位与实际支持分开

### 9.1 四种独立状态

系统分别记录：谁名义上在位、谁有权访问哪些公共资源、谁愿意接受其协调、谁实际控制某地点或物资。它们可以不一致。

获得职位不增加全图识别，也不修改 NPC 的私人目标；失去职位不删除旧友谊、恩情、恐惧或私人所有权。

### 9.2 更替过程

成员提出异议和替代方案；若存在有效更替提议，按现行组织约定收集回应与授权，提交明确的职位变更事件。条件不满足则不更替，不为了戏剧补足支持者。

形式上在位但无人愿意执行的局面也可以存在。其结果应来自成员的实际回应，不用隐藏导演惩罚玩家。

职位变更后，公共仓库的访问范围、可代表组织签订的协议和协调任务的权限随之更新。未完成事务按权责归属移交：组织债务不自动变成个人债务，私人承诺不因卸任自动消失。

### 9.3 失位之后的可玩性

玩家仍可请求一般工作、做私人交易、照料伤员、参与自愿行动、离开或提议新的合作。其权限与普通成员遵守同一套规则。

失去职位不自动驱逐、不清空私人背包、不重置记忆。若发生额外处分，必须有新的明确行为。允许失败带来损失，不允许用无因果的重置替代社会后果。

恢复领导权需要新支持、有效提议和新的历史，不提供“剧情保证重新称王”。也允许玩家永远不再担任首领。

## 10. 姓氏、担保与集体责任

姓氏通过可观察身份线索和传播经历影响相遇。一个成员报告家族名称，是身份主张，不是强制让对方相信的系统命令。

对外担保必须说明范围：保证某批货物、承诺一定补偿，或愿意组织一次护送。不得一句“以家族名义担保”无限质押全体成员财物。

同一事件可以提升某个人的信用，却损害组织信用；外界也可以不把未经授权的行为算到整个团体身上。记录观察者如何归因，不能把全局声誉值广播给所有人。

## 11. 玩家参与位置

| 参与位置 | 可以做什么 | 世界怎样回应 |
|---|---|---|
| 普通探险者 | 发现路线、帮助伤员、交换私人物品 | 获得局部信息和个人关系 |
| 运输或护送成员 | 接受条款、履行、退出或协商报酬 | 影响交付、信任与后续邀请 |
| 担保人与协调者 | 在权限内承诺、谈判和分配 | 承担明确范围内的责任 |
| 部落首领 | 提议集体目标、使用授权、争取支持 | 成员可以认可、反对或撤回授权 |
| 失位者或离开者 | 工作、贸易、重新结伴、回访旧营地 | 旧历史保留，职位权限改变 |

玩家离开某个区域时，世界逻辑不因镜头移开而停止；程序关闭后的离线进展仍属单独功能，本扩展不承诺后台持续运行。

## 12. 信息边界与可读性

不通过全知外交面板决定谁知道什么。运输者、目击者、公开回应和回报带来信息。转述保留来源，重复同一来源的消息不能被当作多个独立证据。

正常界面展示玩家已知的协议、路线、成员回应、公开职位与近期原因。私有库存、隐藏主张和全部关系图只出现在明确的调试视图中。

“我听说他们失约”可以是角色台词；“他们故意背叛”不能被无证据的系统播报判定为真。失位预警应来自已经发生、玩家可观察或被告知的变化，而不是泄露他人的秘密心理。

## 13. 不能做偏的约束

1. 不能把部落做成控制所有人的单一大脑。
2. 不能把自主性做成随机拒绝和无限协商。
3. 不能把资源匮乏自动推导为战争。
4. 不能把派系形成等同于分裂或敌对。
5. 不能为保证故事密度强迫失踪、背叛或罢免。
6. 不能用廉价重复赠与和重复传闻无限刷关系。
7. 不能让所有 NPC 无视眼前利益，只围绕玩家行动。
8. 不能因为更换模型而重置人物、协议或历史。

## 14. 对旧规格的明确细化

| 旧表述可能造成的歧义 | 本轮采用的口径 |
|---|---|
| 组织不是按钮 | 按钮可以提出组织，不能凭空产生执行力 |
| 组织必须被外部承认才存在 | 内部有效约定可成立；外部识别单独记录 |
| 目击者置信度就是 1 | 目击信息仍受遮挡、身份识别和感知范围限制 |
| 每次转述必须随机失真 | 来源必保留；可丢细节，不强制每次编造错误 |
| 首个 Demo 是借粮 | 当前执行基线已改为狩猎—救援—分配；借粮保留作后续测试 |
| 观察生成故事 | 事实和因果依赖不因无人观察而不存在；观察形成叙事解释 |
| 不可逆意味着不能修复 | 过去不可删除；可以通过新行动补偿、和解和重建 |
| 资源、生命守恒 | 资源转移与产消有账；生命遵守伤害/治疗规则，不把生命值当作守恒物资 |

以上是文档层的语义约定；涉及存档、参数或实现的变更，仍需在工作区确认后执行。

## 15. 扩展顺序

| 扩展 | 可验收目标 | 暂不做 |
|---|---|---|
| E1 两营交往 | 有真实交易、交付、延误、搜救和修复 | 全地图经济 |
| E2 集体决定与派系 | 成员回应影响集体行动；合作记录形成群体 | 完整制度编辑器 |
| E3 领导更替与有限冲突 | 玩家可失位后继续游玩；冲突可停止 | 大型攻城、全面吞并 |
| E4 三营网络 | 第三方担保、替代交易伙伴、联盟与中立 | 数十部落并发模拟 |

E2 的有限授权基础会在 E1 中先实现；E3 的伤害与救援复用现有已验收底座。每层完成后可以暂停扩展，先验证体验。

## 16. 何时才算方向成立

在 NPC 自行运行、玩家局部介入的情况下，能够追溯一次实际交付或损失如何改变信息、关系、合作和后续选择。平静合作与冲突升级都能成立；至少一条经过正常操作的路线支持玩家失去职位后继续生活。

验收不得要求每个种子都发生战争、分裂或罢免。固定测试可构造前提并验证规则；自由试玩只观察结果，不偷偷保证结局。
