# K-I-N 游戏项目设计规格 v0.5

**版本：v0.5｜2026-09-29**  
**性质：主设计规格 / 从理念进入可执行设计的第一版**  
**上游基线：Jev × 因果世界模拟 v0.4**

---

# 0. v0.5 的目的

v0.4 已经回答了一个根本问题：

> **我们相信怎样的世界才算“活着”？**

它建立了九条世界公理、WorldCore 的地位、World State / Belief State 分离、主体成长、路径依赖、共同演化与 Historical Leverage 等核心原则。

v0.5 不再继续无限扩写理念，而开始回答三个更直接的问题：

1. **玩家到底在玩什么？**
2. **这个世界由哪些可执行系统构成？**
3. **第一版原型究竟验证什么？**

因此本项目从 v0.5 起采用六层结构：

```text
L1 核心哲学：为什么做？哪些原则不能被破坏？
L2 玩家体验：玩家每分钟、每小时、每局到底在做什么？
L3 世界模拟：世界如何结算资源、行动、空间、时间与后果？
L4 社会因果：事件如何沉淀为记忆、关系、身份、组织与新选择？
L5 技术架构：规则系统、Jev、Memory、Belief、History Ledger 如何分工？
L6 MVP 与验证：最小切片做什么？什么算真正跑通？
```

六层不是六套彼此独立的系统，而是一条从设计意图到工程验证的连续链。

# L1. 核心哲学：设计宪法

## 1.1 项目一句话定义

> **K-I-N 不是让 AI 替设计师写剧情，而是让有限主体在共享世界中持续选择，让选择形成历史，让历史沉淀成关系与结构，再让玩家从这些痕迹中生活、介入并发现故事。**

## 1.2 九条世界公理

### 公理 1：世界先于故事
世界运行不负责表演剧情。

### 公理 2：选择生成历史
未被选择的路径成为反事实，实际选择成为历史。

### 公理 3：观察生成故事
故事是观察者对历史的因果压缩，不是 WorldCore 的底层事实。

### 公理 4：主体只对自己的世界模型行动
`Belief State != World State`。

### 公理 5：后果必须由世界结算
模型只能提出行动意图，不能凭语言改变资源、伤害、死亡、位置与所有权。

### 公理 6：历史必须产生路径依赖
过去必须真实限制或改变未来，而不是只留在日志里。

### 公理 7：反馈塑造主体
经历必须能够改变未来的信念、关系、策略、习惯或目标优先级。

### 公理 8：主体反过来塑造环境
关系、组织、制度必须由持续行动维持，而不是由文本声明存在。

### 公理 9：稳定与变化必须分层
Hard / Semi-Stable / Liquid 三层同时存在；不是所有东西都随机，也不是所有东西都固定。

## 1.3 三句项目核心

> **选择生成历史。**  
> **观察生成故事。**  
> **反馈塑造主体，主体反过来塑造世界。**

## 1.4 “人”与“工蜂”的分界

传统经营/策略游戏常把人口视为功能单位：

```text
玩家下令
→ 单位执行
→ 产出资源
```

K-I-N 的主体不是命令接口，而是具有：

- 自身需求
- 局部认知
- 历史记忆
- 多维关系
- 承诺与债务
- 身份归属
- 风险偏好
- 当前目标
- 对命令来源的判断

因此同一个“去伐木”的要求，十个人可能得到十种判断：

```text
因为我是你的雇员，所以去。
因为欠你人情，所以去。
因为这是家族义务，所以去。
因为冬天快到了，所以去。
因为害怕你，所以表面答应。
因为我不信任你，所以拒绝。
因为我要求报酬，所以先谈条件。
```

这不是随机拒绝，而是**关系与约束参与决策**。

# L2. 玩家体验与核心循环

## 2.1 玩家幻想

项目当前最适合的幻想不是“我从零点科技树一路升到帝国”，而是：

> **我带领一小群人进入一个陌生世界；我们彼此依赖、冲突、记住对方；一些关系变成承诺，一些承诺变成家族，一些家族变成派系；多年以后，当别人听见我的姓氏、旗号或组织名称时，他们的反应来自真实历史。**

起点应当足够小：

```text
6–12 名探险者
一个未知区域
有限资源
有限信息
没有预写主线
```

但系统必须允许这些微观关系逐渐生长为：

```text
朋友 / 仇敌
→ 家庭 / 家族
→ 营地 / 派系
→ 商会 / 部落
→ 城镇 / 政体
```

## 2.2 核心玩法不是“建造升级”，而是“介入关系与后果”

玩家可以：

- 探索未知区域
- 获取、交换和分配资源
- 请求、承诺、借贷、赠与、拒绝
- 招募、合作、命令、谈判
- 调停冲突或制造冲突
- 传播、隐瞒或验证信息
- 给予身份、姓氏、职位与庇护
- 建立营地与长期资源结构
- 介入他人的关系网络
- 承担自己过去行为产生的社会后果

核心循环：

```text
观察局部世界
→ 做出行动 / 承诺 / 分配
→ WorldCore 结算真实后果
→ NPC 形成不同记忆与认知
→ 关系与声誉变化
→ 群体结构发生变化
→ 新的选择空间出现
→ 玩家再次介入
```

## 2.3 关系不是一个附属系统，而是主要游戏空间

资源系统提供压力，关系系统决定压力如何被社会消化。

同样的粮荒可以产生：

- 分享
- 借债
- 囤积
- 偷窃
- 报复
- 新的互助规范
- 对某个家庭的依赖
- 对某个首领的不满
- 第二营地

因此本项目的“内容”不是预制任务数量，而是不同系统之间可形成多少新的社会因果链。

## 2.4 关系尺度连续性（Micro–Macro Continuity）

这是 v0.5 新增的重要体验要求。

很多游戏在宏观层承认玩家是国王、领主、派系首领，但在微观街道层，普通 NPC 对此几乎没有反应；宏观势力系统与微观人物系统是断开的。

K-I-N 要求身份具有**尺度穿透性**：

```text
个人行为
→ 形成声誉
→ 声誉附着到姓氏 / 家族 / 组织
→ 宏观地位改变
→ 普通 NPC 在微观相遇中根据自己知道的信息作出反应
```

一个“国王”走在街上是否被认识，不由一个全局标签直接决定，而由：

- 对方是否见过他
- 是否听说过他的名字或外貌
- 是否认识他的徽记、护卫、姓氏
- 本地传播程度
- 对该家族 / 王国的态度
- 当前环境是否允许识别

宏观身份必须落回个体经验，个体经验也必须能够反过来塑造宏观结构。

# L3. 世界模拟层：WorldCore

## 3.1 WorldCore 的职责

WorldCore 是整个项目最重要的基础设施。

它负责回答：

```text
这个行动是否允许？
需要什么资源？
发生在哪里？
耗时多久？
是否成功？
谁失去了什么？
谁获得了什么？
谁受伤、死亡、移动、占有、欠债？
什么状态被永久改变？
```

模型负责“想做什么”；WorldCore 负责“到底发生了什么”。

## 3.2 三层稳定结构

### Hard Layer
高确定性，不能被语言模型随意更改：

- 时间
- 空间
- 位置
- 资源
- 库存
- 所有权
- 生死
- 伤害
- 建造
- 生产耗时
- 工具损耗

### Semi-Stable Layer
可以变化，但需要历史支撑：

- 长期关系
- 家族
- 姓氏归属
- 职位
- 组织
- 制度
- 法律
- 习惯
- 社会角色

### Liquid Layer
允许快速适应：

- 当前计划
- 当前判断
- 谈判策略
- 临时联盟
- 风险解释
- 对某条消息的即时看法

## 3.3 History Ledger

每一个真正执行的社会事件都必须生成结构化历史记录。

最小事件字段：

```yaml
event:
  id:
  tick:
  type:
  actor:
  target:
  location:
  preconditions:
  action_intent:
  world_changes:
  participants:
  direct_witnesses:
  indirect_receivers:
```

History Ledger 保存**事实与可观察输入**，不把模型内部不可验证的心理解释写成世界事实。

例如可以记录：

```text
A 拒绝给 B 食物；A 当时库存为 1；C 在场。
```

不能直接把：

```text
“A 因为自私所以拒绝。”
```

写成客观事实。

## 3.4 Historical Leverage

新增功能优先级不看“增加了多少台词/物品”，而看它能产生多少长期历史。

内部粗略指标：

```text
Historical Leverage
≈ New Choices
× Consequence Diversity
× Persistence
× Cross-Agent Effects
```

例如“借债与偿还”通常比“增加 1000 句闲聊”拥有更高历史杠杆，因为它可以自然产生：

- 信任
- 违约
- 人情
- 报复
- 继承债务
- 家族声誉
- 组织信用

# L4. 社会因果层：从事件长成社会

## 4.1 主链

v0.5 将第一个核心社会系统正式定义为：

```text
Event
→ Perception
→ Memory
→ Belief
→ Relationship
→ Identity
→ Organization
→ Choice
→ New Event
```

关键不是让 NPC “记住所有事”，而是让**少数有社会意义的事件留下不同形式的痕迹**。

详细规格见：

`docs/systems/Social_Causality_System_v0.1.md`

## 4.2 Event → Memory

不是所有事件都进入长期记忆。

事件应计算记忆显著度（Salience），参考：

- 生存影响
- 情绪强度
- 稀有程度
- 关系重要性
- 身份意义
- 不可逆程度
- 事件是否违背预期

例如：

```text
玩家路过我身边
→ 低显著度

饥荒时玩家把最后一份食物给我
→ 高显著度
```

## 4.3 Memory → Relationship

记忆不能无限累积后每次全部重新读取。

长期交互必须压缩为多维 Relationship State，例如：

```yaml
relationship:
  trust: 0.72
  fear: 0.10
  respect: 0.55
  obligation: 0.80
  affection: 0.34
  resentment: 0.02
  familiarity: 0.65
```

关系绝不能退化为单一“好感度”。

一个人可以同时：

```text
不喜欢你
不信任你
尊敬你的能力
欠你人情
害怕你的家族
```

## 4.4 Belief：社会传播的不是事实，而是认知

World State：

```text
玩家杀死了 A。
```

但社会中可能同时存在：

```text
B：亲眼看到，置信度 1.0
C：听 B 说，置信度 0.7
D：听到模糊传闻，置信度 0.3
E：相信其实是另一个人干的
```

因此社会结构由：

```text
事实
+
传播路径
+
来源可信度
+
既有偏见
+
后续验证
```

共同形成。

## 4.5 Identity：姓氏必须成为可追责的社会身份

姓氏不是昵称，也不是 UI 装饰。

当一个 NPC 接受某个姓氏 / 家族身份后，至少意味着世界中出现了以下部分关系：

- 成员自我认同
- 其他成员对其身份的承认
- 某种共同义务或庇护预期
- 声誉可以在成员之间发生有限迁移
- 外部主体可以对“个人”和“家族”分别持有认知

因此决策输入可以同时包含：

```text
我怎么看这个人？
+
我怎么看他的家族？
+
我怎么看他所属的组织？
+
当前情境是什么？
```

当玩家的姓氏因为真实历史获得重量时，“报出家门”才会成为玩法，而不是一段固定台词。

## 4.6 个人声誉与集体声誉必须分离

```text
Reputation(Person)
!=
Reputation(House)
!=
Reputation(Faction)
```

它们可以相互影响，但不能直接等同。

例如：

- 一个家族整体令人畏惧，但其中某成员可能被认为软弱
- 玩家本人值得信任，但其组织可能因其他成员行为声名狼藉
- 一个成员的严重背叛可能污染家族声誉，但污染程度取决于身份显著性与外界归因

## 4.7 组织不是按钮，而是稳定关系网络

第一原则：

> **组织必须被世界“承认出来”，而不是仅被 UI “创建出来”。**

玩家可以提出名称、旗号、姓氏、规则，但组织真正存在，需要事实支撑，例如：

```text
共同身份
+
稳定成员关系
+
资源共享 / 权利义务
+
共同防御或行动
+
内部承认
+
外部识别
+
持续时间
```

当这些条件达到一定稳定程度，WorldCore 才生成 Semi-Stable Organization State。

组织也必须能够瓦解：

- 成员不再承认
- 共同资源失效
- 领导权失去执行力
- 外部识别消失
- 内部分裂形成新的稳定网络

## 4.8 微观关系如何长成宏观结构

K-I-N 的社会尺度采用双向链：

```text
微观：A 帮助 B
↓
关系：B 欠 A 人情
↓
传播：C / D 知道 A 会保护自己人
↓
身份：A 的姓氏获得“庇护”声誉
↓
组织：更多人寻求加入 / 联盟
↓
宏观：该家族获得政治重量
↓
反作用：陌生 NPC 因家族声誉改变对 A 成员的行为
```

因此宏观势力不是独立的策略游戏 UI，而是微观历史长期压缩出的稳定结构。

# L5. 技术架构

## 5.1 核心分工

### WorldCore
负责：事实、约束、执行、结算。

### Perception System
负责：谁能感知什么，以及信息损失。

### Belief System
负责：主体相信什么、信息来源、置信度与冲突认知。

### Memory System
负责：事件显著度、短期记忆、长期记忆、压缩与遗忘。

### Relationship System
负责：多维关系状态及其更新。

### Identity / Organization System
负责：姓氏、角色、家族、组织的稳定存在与变化条件。

### Jev / Local Choice Operator
负责：在主体的局部认知与当前约束内选择行动意图。

### History Ledger
负责：不可逆历史事实。

### Observer Layer
负责：向玩家展示现场、编年史、角色叙事与因果视图。

## 5.2 决策循环

```text
World State
↓
Perception Filter
↓
Belief Update
↓
Relevant Memory Retrieval
↓
Need / Goal Update
↓
Relationship / Identity Context
↓
Candidate Action Generation
↓
Jev / Rule Decision
↓
Action Intent
↓
WorldCore Validation
↓
Execution
↓
History Event
↓
Witness / Rumor Propagation
↓
Memory + Belief + Relationship Update
↓
下一轮
```

## 5.3 主体状态不是模型权重

主体长期状态定义为组合体：

```text
Policy / Model
+
Belief
+
Memory
+
Relationships
+
Skills
+
Tools
+
Commitments
+
Identity
+
World Access
+
Current Context
```

第一阶段不依赖在线 RL 或实时微调。

## 5.4 数据必须可解释、可回放

任何重要社会变化都必须能够追溯：

```text
这个人为什么开始害怕玩家？
→ 哪些事件？
→ 他亲眼看到还是听说？
→ 信息来源是谁？
→ 哪个关系维度发生变化？
→ 哪次选择因此改变？
```

如果无法追溯，就很难区分“涌现”与“随机噪声 / 模型幻觉”。

## 5.5 LLM 的使用边界

适合模型：

- 局部行动选择
- 复杂情境判断
- 谈判意图
- 自然语言表达
- 对已有 Belief 的解释

不适合模型直接负责：

- 库存
- 资源守恒
- 伤害与死亡
- 地理位置
- 所有权
- 历史事实修改
- 组织是否真实存在的最终判定

# L6. MVP 与验证标准

## 6.1 MVP 不是“做一个开放世界”

第一版只验证：

> **经历是否真的改变下一次社会选择，并且这种改变能够通过多人互动反过来改变共享世界。**

## 6.2 Slice 0：四人借粮

初始：

```text
A：有 2 份粮
B：没有粮
C：现场目击
D：只通过 C 得知
```

流程：

```text
B 向 A 借粮
→ A 接受 / 拒绝
→ WorldCore 改变真实库存
→ C 获得直接记忆
→ D 获得二手信息
→ B/C/D 形成不同 Belief
→ Relationship State 变化
→ 第二次资源压力
→ 四个人选择发生分叉
```

验收：第二轮行为必须可追溯到第一轮经历，而不是随机换台词。

## 6.3 Slice 1：姓氏 / 家族声誉最小切片

新增 4–6 人：

1. 玩家拥有自定义姓氏 `Varen`
2. 玩家长期保护 NPC_B
3. B 主动接受 / 被允许使用 `Varen` 姓氏
4. 第三方 C 目击 Varen 成员共同防御
5. 信息传播给 D
6. D 后来第一次遇到 B

关键验证：

```text
D 从未认识 B
但 D 对 “Varen” 已经有 Belief
→ D 的第一次互动受到家族声誉影响
```

这证明“身份”已经跨越个人记忆，形成 Semi-Stable 社会结构。

## 6.4 Slice 2：不是工蜂

玩家提出一个群体任务，例如：

```text
10 人去采木，为冬季修屋。
```

系统必须允许出现：

- 接受
- 拒绝
- 要求交换
- 因义务接受
- 因恐惧接受
- 拖延
- 优先处理自己的家庭需求

这些差异必须来自各自主体状态，而不是纯随机概率。

## 6.5 Slice 3：12 人河谷营地

当上述切片稳定后，再扩大到：

```text
12 名探险者
一个河谷
有限资源
一个第二营地位置
捕鱼 / 采集 / 烹饪 / 建造

```

不设置主线。

运行 30 个游戏日后人工回顾。

## 6.6 成功标准

### A. 因果一致性
日志中的事情必须真实改变世界。

### B. 路径依赖
同一主体 Day 30 的行为受到 Day 1–29 的经历影响。

### C. 认知差异
同一事件可以产生不同 Belief，并能追溯信息路径。

### D. 关系可解释
关系不是随机浮动；重要变化能够找到事件来源。

### E. 身份具有重量
姓氏 / 家族 / 组织能改变陌生主体的行为，但影响依赖其认知而不是全知标签。

### F. 微观—宏观连续
个人行为能够形成组织声誉，组织状态也能反过来影响个体相遇。

### G. 非工蜂性
NPC 不总是把玩家命令当作最高优先级。

### H. 历史分叉
相同初始规则、多次运行应形成不同关系与组织结构，而不只是不同对白。

### I. 观察价值
运行结束后，玩家愿意停下来研究发生过什么，并能发现不止一种合理叙事。

## 6.7 明确不追求

第一阶段不追求：

- 大地图
- 数百 NPC
- 完整国家模拟
- 全自由自然语言行为
- 在线强化学习
- 全角色长期推理
- 自动生成“史诗剧情”
- 复杂战斗系统
- 完整科技树

如果四人借粮与姓氏传播都没有真正产生第二阶选择变化，那么增加 100 个 NPC 只会放大空洞。

# 7. v0.5 新增的关键概念

相对 v0.4，本版正式加入：

1. **六层项目结构**：从设计哲学到 MVP 验证分层，不再把理念与实现混写。
2. **Social Causality System**：Event → Memory → Belief → Relationship → Identity → Organization → Choice。
3. **关系作为主要玩法空间**：关系不是 UI 数值附属，而是选择条件本身。
4. **非工蜂原则**：NPC 对玩家要求拥有自身判断基础。
5. **Identity as Social Contract**：姓氏 / 家族身份是带义务、庇护、声誉与追责的社会状态。
6. **Micro–Macro Continuity**：宏观势力身份必须能够穿透到微观 NPC 相遇。
7. **Emergent Recognition**：家族与组织必须被成员和外部世界逐渐承认出来，而不是仅由按钮声明。
8. **Personal / House / Faction Reputation 分离**：个人与集体声誉相互影响但不等同。
9. **姓氏最小技术切片**：验证陌生人能否仅凭传播历史对家族成员形成不同初始反应。

# 9. v0.5 当前项目判断

K-I-N 当前真正要证明的，不是：

> “大模型 NPC 能不能聊得像真人？”

而是：

> **当一个主体做了一件事，世界能否记住；别人能否以不同方式知道；这些认识能否沉淀成关系；关系能否长成身份与组织；这些结构又能否真实改变下一次选择。**

如果这条链成立，K-I-N 才拥有继续向开放世界、部落、家族、派系与文明扩张的基础。

如果这条链不成立，无论增加多少地图、建筑、对白和模型参数，项目仍然只会是一个会聊天的沙盒。
