# Jev × 因果世界模拟
## 从“选择生成历史”到“主体与世界共同生长”

**版本：v0.4｜2026-09-28**  
**性质：核心设计文档 / 长期迭代基线**  
**上游文档：**
- 《涌现式开放世界：从“脚本 NPC”到“持续运转的社会”》
- 《Jev × 涌现式开放世界 v0.2》

> **v0.4 的关键变化：**  
> 在 v0.3“选择生成历史，观察生成故事”的基础上，加入第三个闭环：
>
> **反馈塑造主体，主体反过来塑造世界。**
>
> 项目目标不再表述为“让 AI 自动生成故事”，而是：
>
> **让世界持续生成真实的选择与后果，使历史自行形成；故事则由观察者对这段历史进行因果压缩后产生。**

---

# 0. 项目的重新定义

此前我们把项目描述为：

> 给 NPC 一个局部决策器，让世界自己产生故事。

这个说法仍然成立，但已经不够精确。

现在更准确的定义是：

> **我们不直接生成故事。**
>
> 我们生成一个能够持续产生：
>
> **可能性 → 选择 → 后果 → 新可能性**
>
> 的世界。

NPC 负责选择。

规则系统负责后果。

社会网络负责把局部后果扩散。

时间负责把选择积累成不可逆的历史。

观察者负责从历史中辨认因果。

最终形成“故事”。

因此，项目真正要构建的不是：

```text
AI Story Generator
```

而是：

```text
Causal World Simulation
因果世界模拟
```

或更准确一点：

```text
Procedural History Generation
程序化历史生成
```

**故事是这个系统的观察结果，而不是底层目标。**

---

# 1. 核心本体：世界、选择与观察

## 1.1 选择之前只有可能性

假设某个时刻，NPC 可以：

```text
A：借粮
B：偷粮
C：离开营地
D：忍耐
```

那么此时系统拥有的是一个可能性集合：

\[
\Omega_t = \{A,B,C,D\}
\]

它还不是故事。

当 NPC 真正选择：

\[
C_t(\Omega_t) = B
\]

系统才进入新的世界状态：

\[
S_t \rightarrow S_{t+1}
\]

A、C、D 没有发生。

B 成为历史。

于是第一次出现：

```text
发生了什么
vs
本可以发生什么
```

这个差值，就是反事实空间。

而反事实空间是：

- 遗憾
- 幸运
- 牺牲
- 错过
- 悲剧
- 命运感

能够存在的前提。

---

## 1.2 第一次坍缩：选择坍缩

这里的“坍缩”是系统论与认识论意义上的隐喻，不是对量子物理机制的主张。

每一次选择都执行同一个结构：

```text
多种可能
   ↓
一次选择
   ↓
一个实际状态
   ↓
新的可能性展开
```

形式上：

\[
\Omega_t
\xrightarrow{choice}
S_{t+1}
\xrightarrow{world}
\Omega_{t+1}
\]

然后再次：

\[
\Omega_{t+1}
\xrightarrow{choice}
S_{t+2}
\]

所以历史不是一条预先存在的线。

更像：

```text
           A
         /
S0 ───── B  ← 实际发生
         \
           C
           │
           ├── D
           ├── E ← 实际发生
           └── F
                  │
                  ...
```

**时间线，是可能性树不断被选择切出来的一条路径。**

---

# 2. “选择的对称重复”

我们进一步保留今晚最重要的一个概念：

> **选择在结构上不断重复，但历史不会重复。**

每个时刻都具有近似相同的拓扑：

```text
可能性展开
↓
局部主体判断
↓
选择
↓
后果
↓
新可能性展开
```

因此它是一种：

# **结构上的对称重复**

而不是结果上的重复。

可以写成：

```text
多 → 一 → 多 → 一 → 多 → 一
```

或者：

```text
展开 → 破缺 → 再展开 → 再破缺
```

规则结构高度重复。

但因为每一次选择都会改变：

- 资源
- 关系
- 信息
- 身份
- 信任
- 地理位置
- 权力结构
- 记忆

所以下一次的 \(\Omega\) 已经不同。

因此：

> **相同的选择机制，不会产生相同的历史。**

这将成为整个游戏循环的基础。

---

# 3. 第二次坍缩：观察生成故事

世界中发生事件，不等于世界中天然存在一个“故事”。

假设一天发生：

```text
甲捕鱼
乙拒绝借粮
丙受伤
丁搬家
戊和守卫争吵
市场食物减少
天气转坏
一个工具损坏
```

这些首先只是事件。

底层真实结构更像一个巨大事件图：

\[
G=(V,E)
\]

其中：

- \(V\)：事件
- \(E\)：状态依赖、传播、参与、资源变化、信息来源等关系

观察者后来看到：

```text
食物短缺
↓
乙拒绝借粮
↓
甲改去偷窃
↓
守卫处罚甲
↓
甲的家族与守卫发生冲突
↓
营地分裂
```

于是观察者说：

> “这场分裂始于一次粮食危机。”

这一句话不是 WorldCore 自动拥有的“真理”。

它是观察者把复杂历史压缩成了一条因果解释。

因此存在第二种坍缩：

```text
大量历史事件
↓
观察者选择哪些事件重要
↓
建立因果联系
↓
形成故事
```

所以本项目采用两个不同层次：

### 第一层：行动坍缩

```text
可能做什么
↓
真正做了什么
```

产生**历史**。

### 第二层：观察坍缩

```text
无数已经发生的事情
↓
哪些事情被理解为彼此有关
```

产生**故事**。

---

# 4. 因此，我们不再让 NPC “写故事”

这是 v0.3 最重要的架构修正。

错误方向：

```text
模型：
“请生成一个戏剧性的剧情。”
```

这只是把人类编剧替换成 AI 编剧。

我们真正需要的是：

```text
NPC：
在当前认知、欲望、关系和资源条件下，
你会选择哪个允许行动？
```

然后：

```text
WorldCore：
这个行动真实造成了什么？
```

再然后：

```text
其他 NPC：
他们实际知道了什么？
他们如何解释？
他们接下来怎么选？
```

故事最后才出现。

因此：

> **NPC 不负责故事。NPC 负责行动。**
>
> **世界不负责戏剧。世界负责后果。**
>
> **观察者负责叙事。**

---

# 5. Jev 的新定位：局部“对称破缺器”

Jev 在这个系统里不再被描述成：

> AI NPC 的大脑。

这太宽泛。

更准确的角色是：

# **Local Choice Operator**
## 局部选择算子

输入：

```text
NPC 当前认知
+
当前需求
+
人格倾向
+
近期记忆
+
关系
+
可尝试行动集合
```

输出：

```text
当前更可能选择哪个行动
```

即：

\[
Jev(B_t, N_t, P_t, M_t, A_t)
\rightarrow
a_t
\]

其中：

- \(B_t\)：Beliefs，NPC 认为世界是什么
- \(N_t\)：Needs，当前需求
- \(P_t\)：Personality，相对稳定人格倾向
- \(M_t\)：Memory，相关记忆
- \(A_t\)：Actions，当前允许尝试的行动集合
- \(a_t\)：实际行动意图

Jev **不决定世界结果**。

它只完成：

```text
Ωt
↓
选出一个局部行为
```

真实后果由 WorldCore 计算。

---

# 6. NPC 不对“真实世界”行动，而是对“自己的世界模型”行动

这是 v0.3 相比 v0.2 的第二个核心升级。

必须严格区分：

## World State

真实世界：

```text
粮仓还有 3 份粮食。
A 没有背叛 B。
北方道路已经被强盗封锁。
```

## Belief State

某个 NPC 的认知：

```text
他以为粮仓还有 10 份粮食。
他相信 A 背叛了 B。
他不知道北方道路已经被封锁。
```

NPC 决策只能读取：

> **Belief State**

而不能直接读取完整 World State。

于是自然产生：

```text
事实
≠
认知
```

而社会复杂性正大量来自这个差值。

---

## 6.1 一个最小社会涌现例子

真实情况：

```text
A 没有背叛 B。
```

但 C 错误相信：

```text
A 背叛了 B。
```

于是：

```text
C 疏远 A
↓
A 发现 C 对自己敌视
↓
A 开始防备 C
↓
C 看到 A 的防备
↓
C 更确信自己的判断
↓
冲突升级
```

最初没有背叛。

最后却产生真实冲突。

这意味着：

> **认知可以通过选择制造现实。**

这一层将是未来社会模拟真正重要的发动机之一。

# 7. 世界的四层架构

v0.3 将整个系统重新划为四层。

```text
┌──────────────────────────────┐
│ 4. Observer Layer            │
│ 观察、因果压缩、叙事呈现       │
└──────────────↑───────────────┘
               │ 历史事件
┌──────────────┴───────────────┐
│ 3. History Layer             │
│ 已经发生、不可逆的事实与痕迹    │
└──────────────↑───────────────┘
               │ 执行结果
┌──────────────┴───────────────┐
│ 2. Agent Layer               │
│ 感知、信念、记忆、欲望、选择     │
│ Jev 位于这里                  │
└──────────────↑───────────────┘
               │ 世界约束
┌──────────────┴───────────────┐
│ 1. Law Layer                 │
│ 资源、物理、时间、空间、生产规则  │
└──────────────────────────────┘
```

---

## 7.1 Law Layer：世界法则

必须高度确定。

包括：

- 食物数量
- 生产速度
- 时间
- 移动
- 伤害
- 距离
- 天气
- 库存
- 生死
- 建筑
- 工具损耗
- 资源转移

这里尽量不使用生成模型。

---

## 7.2 Agent Layer：主体认知与选择

包括：

- 感知
- 信息来源
- Belief State
- 人格倾向
- 情绪
- 关系
- 当前需求
- 当前目标
- 记忆
- 行动候选
- Jev 判断

这一层的核心不是“聪明”。

而是：

> **局部、有限、带偏差的合理性。**

---

## 7.3 History Layer：不可逆痕迹

任何真正执行过的行为，都留下事实。

例如：

```text
谁给了谁食物
谁看见了
谁拒绝了谁
谁受伤
谁死了
谁离开
谁欠了谁
哪栋房子被烧毁
哪条路被封锁
谁成为新的首领
```

**模型不能回头修改历史。**

---

## 7.4 Observer Layer：叙事发生的位置

观察者可以是：

- 玩家
- 游戏内某个 NPC
- 史官
- 世界日志
- 后期的自动摘要系统
- 玩家社区

同一段 History，可以被不同观察者压缩为不同故事。

这是允许的。

因为故事是解释层。

事实层必须保持一致。

---

## 7.5 Adaptation Loop：主体与世界共同变化

v0.3 里，历史主要被理解为“过去发生过什么”。

v0.4 增加一个更严格的要求：

> **历史不仅必须改变世界，也必须有能力改变产生下一次选择的主体。**

完整闭环从：

```text
World
↓
Agent
↓
Choice
↓
Consequence
↓
History
```

升级为：

```text
                ┌───────────────┐
                │     World     │
                └───────┬───────┘
                        ↓
                ┌───────────────┐
                │     Agent     │
                └───────┬───────┘
                        ↓
                     Choice
                        ↓
                   Consequence
                        ↓
                     History
                    ↙       ↘
             World changes   Agent changes
                    ↘       ↙
                     New State
                        ↓
                    New Choice
```

因此真正的长期系统不是“NPC 在固定策略下重复行动”，而是：

\[
(World_t, Agent_t)
\rightarrow
Choice_t
\rightarrow
(World_{t+1}, Agent_{t+1})
\]

其中：

\[
Agent_{t+1} \neq Agent_t
\]

并不要求每一轮都训练模型权重。

第一阶段中，主体变化应优先由这些低成本、可解释结构承担：

- Belief 更新
- Memory 累积与遗忘
- Trust / Resentment 改变
- Habit 形成
- Goal Priority 改变
- Risk Preference 的缓慢漂移
- 技能熟练度
- 承诺与债务
- 社会身份变化

**在线微调或权重学习属于远期能力，不应成为 MVP 的前置条件。**

# 8. 游戏设计者的新角色：选择空间工程师

传统编剧决定：

```text
接下来发生什么。
```

本项目的设计者更应该决定：

```text
什么可以发生。
什么代价会发生。
什么信息可以被谁知道。
什么后果不可逆。
```

因此可以把游戏设计者定义为：

# **Choice-Space Engineer**
## 选择空间工程师

设计目标不是：

> 让玩家走到结局 X。

而是：

> 设计一个足够丰富、足够稳定、足够可理解的选择空间，使不同主体不断产生新的历史。

设计对象从“剧情节点”转变成：

- 可行动作
- 行动成本
- 信息权限
- 社会关系
- 资源依赖
- 传播机制
- 承诺
- 制度
- 后果
- 不可逆性

# 9. Narrative Attractor：叙事吸引子，而不是剧情节点

完全没有结构的世界很容易变成噪声。

因此项目仍然需要“作者性”。

但作者性不应该表现为：

```text
Day 20：村长被杀
Day 25：年轻人发动政变
```

而应表现为：

```text
一个逐渐衰老但拒绝交权的首领
一个能力很强但长期受压制的年轻人
一个不断恶化的粮食问题
两个存在旧怨的家庭
一条越来越重要的新商路
```

这些不是剧情。

它们是：

# **Narrative Attractors**
## 叙事吸引子

它们提高某些冲突、合作和结构变化出现的可能性。

但不指定结果。

例如：

```text
粮荒
```

可能导致：

- 偷窃
- 合作
- 配给制度
- 移民
- 战争
- 技术改良
- 新贸易路线
- 什么都没发生，因为天气很快改善

作者只制造张力场。

历史自己决定路径。

# 10. 戏剧性来自哪里

v0.3 不把“戏剧性”写进 NPC 目标。

否则 NPC 会为了好看而行动。

我们只在 Observer Layer 使用一个**启发式指标**来发现“可能值得观察”的历史节点。

一个选择的戏剧潜力可以粗略理解为：

\[
Drama
\propto
Uncertainty
\times
Consequence
\times
Irreversibility
\]

进一步还可以加入：

\[
CounterfactualDistance
\]

即：

> 如果当时选另一个选项，世界会有多不一样？

因此：

```text
今天吃鱼还是肉
```

可能有不确定性，但：

- 后果小
- 可逆性高

所以戏剧性低。

而：

```text
要不要把最后一份药给受伤的陌生人
```

可能同时拥有：

- 高不确定
- 大后果
- 高不可逆
- 大反事实距离

于是容易成为故事节点。

**注意：这个公式只能用于观察和呈现，不允许反过来控制 NPC。**

我们不能为了制造戏剧：

> 偷偷强迫角色选择“更精彩”的行为。

---

# 11. “攻略”问题的重新定义

普通游戏的攻略通常在寻找：

```text
固定输入
→ 最优输出
```

例如：

```text
某装备组合
某刷钱路线
某 Boss 固定打法
```

而本项目希望玩家获得的是：

```text
条件判断能力
```

例如玩家知道：

> “这个领主通常贪婪。”

但贪婪不是：

```text
贿赂 500 金
→ 必定放行
```

真正的状态可能是：

```text
贪婪
+
害怕失权
+
近期刚被调查
+
不信任玩家
+
财政困难
+
妻子知道他的账目
```

于是今天给 500 金，他拒绝。

攻略从：

> “答案是什么？”

变成：

> “在什么条件下这个规律成立？”

因此玩家真正学习的可能是：

- 判断利益
- 判断信任
- 判断权力
- 判断风险
- 判断信息来源
- 判断一个人的真实约束

这正是项目希望建立的“现实知识迁移”。

# 12. 第一版 Demo 重新设计：12 名探险者的河谷

第一版仍然保留“小规模验证”。

但验证问题变化了。

以前问：

> NPC 能不能产生有趣事件？

现在问：

> **一组局部选择，能否形成可追溯、可解释、但事前不可预测的历史？**

---

## 12.1 初始世界

```text
12 名探险者
1 个河谷营地
1 条河
有限食物
有限工具
可建第二营地
```

基础系统：

- 饥饿
- 疲劳
- 健康
- 安全
- 钓鱼
- 采集
- 烹饪
- 建造
- 借还
- 赠与
- 交换
- 搬迁
- 受伤
- 死亡

---

## 12.2 第一批 Narrative Attractors

不写剧情，只设置张力条件。

例如：

### Attractor A：资源依赖

```text
只有 2 人擅长捕鱼
只有 1 人擅长烹饪
```

产生：

> 谁依赖谁？

---

### Attractor B：信息不对称

```text
部分人知道上游还有一个捕鱼点
部分人不知道
```

产生：

> 信息如何传播？

---

### Attractor C：旧关系

```text
A 欠 B 一次帮助
C 不信任 B
D 与 A 是家人
```

产生：

> 关系会不会改变资源分配？

---

### Attractor D：空间分裂可能性

```text
河对岸可以建立第二个营地
```

但不设置：

```text
关系值 < 30 → 自动分裂
```

必须由真实行动完成搬迁。

# 13. 每一个 NPC 最小需要什么

```yaml
npc:
  identity:
    id:
    age:
    role:

  stable_traits:
    risk_tolerance:
    sociability:
    attachment:
    generosity:
    dominance:
    curiosity:

  needs:
    hunger:
    fatigue:
    health:
    safety:

  goals:
    current:
    priority:

  relations:
    trust:
    resentment:
    obligation:
    kinship:

  beliefs:
    known_people:
    known_places:
    believed_resources:
    believed_threats:
    believed_intentions:

  memories:
    recent:
    important:

  commitments:
    active:

  current_action:
    id:
    start_tick:
    interrupt_policy:
```

关键变化：

> `beliefs` 不再只是附属字段。

它必须成为决策的主要输入之一。

# 14. 核心决策循环

```text
World State
    ↓
Perception Filter
    ↓
Belief Update
    ↓
Need / Goal Update
    ↓
Candidate Action Generation
    ↓
Jev / Rule Decision
    ↓
Action Intent
    ↓
WorldCore Validation
    ↓
Execution
    ↓
History Event
    ↓
Observers Receive Partial Information
    ↓
New Beliefs
    ↓
下一轮
```

公式化：

\[
S_t
\rightarrow
P_i(S_t)
\rightarrow
B_{i,t}
\rightarrow
A_{i,t}
\rightarrow
C_{i,t}
\rightarrow
S_{t+1}
\]

不同 NPC 的 \(P_i\) 不同。

所以即便面对同一个真实世界：

\[
B_{1,t}\neq B_{2,t}\neq B_{3,t}
\]

于是自然产生社会分歧。

---

# 15. World Chronicle 必须从“故事日志”升级为“历史账本”

以前我们想记录：

```text
Day 7：A 和 B 发生冲突。
```

v0.3 要求底层保存更细。

例如：

```json
{
  "event_id": "evt_204",
  "tick": 8932,
  "actor": "npc_a",
  "action": "refuse_food_request",
  "target": "npc_b",
  "world_preconditions": {
    "actor_food": 2,
    "target_food": 0
  },
  "actor_beliefs": [
    "food_shortage_likely",
    "npc_b_failed_previous_commitment"
  ],
  "observed_by": ["npc_a", "npc_b", "npc_c"],
  "world_changes": [],
  "relation_changes": [
    ["npc_b", "npc_a", "trust", -0.08]
  ]
}
```

注意：

`actor_beliefs` 记录的是：

> 当时角色持有什么信息。

不是：

> 系统证明了他的“真实心理原因”。

我们只能记录输入、选择和后果。

不能把模型不可观察的内部过程写成事实。

---

# 16. Observer Layer：让玩家“发现故事”

这一层以前不够明确。

现在设计成独立系统。

玩家可以看到三种尺度。

## 16.1 现场

```text
A 拒绝给 B 食物。
```

## 16.2 编年史

```text
Day 12：
B 向 A 请求食物。
A 拒绝。
C 在场。
```

## 16.3 因果视图

玩家之后可以打开：

```text
粮荒
 ├─ A 减少共享
 │   └─ B 对 A 信任下降
 │       └─ B 加入第二营地
 └─ C 开始囤积食物
```

这里非常关键：

> **因果视图应该帮助玩家观察，不应该宣称系统拥有唯一正确叙事。**

未来甚至可以允许：

### 不同观察者生成不同版本的历史

NPC A：

> “B 因为贪婪背叛了营地。”

NPC B：

> “A 在粮荒中拒绝帮助我们。”

玩家：

> “真正的原因其实是捕鱼工具损坏。”

三个叙事可以同时存在。

但底层 History Ledger 只有一套。

---

# 17. 《绝命毒师》给项目的设计启发

这里不复制电视剧剧情，而提炼创作结构。

我们要保留的不是：

> “临时创造角色。”

而是：

> **允许已经产生的状态反过来改变后续创作空间。**

传统剧情生产：

```text
作者知道终点
↓
角色完成剧情功能
```

本项目：

```text
角色产生行动
↓
行动形成新状态
↓
新状态改变后续可行空间
↓
设计者不强行把角色拉回原路径
```

这意味着：

> **路径依赖本身就是内容。**

角色越长期存在，过去发生过的东西就越应该约束未来。

---

# 18. 《黑客帝国》先知式问题：改变选择条件，而不是控制选择

项目未来一个非常重要的机制是：

> 一个主体如何通过信息改变另一个主体的选择空间。

例如：

```text
A 告诉 B：
“C 想害你。”
```

无论真假，这条信息进入 B 的 Belief State。

于是：

\[
B_t \rightarrow B_t'
\]

进而：

\[
\Omega_{t+1}
\neq
\Omega_{t+1}'
\]

也就是说：

> 信息本身是行动。

这将为以后产生：

- 谣言
- 宣传
- 威胁
- 承诺
- 欺骗
- 声誉
- 政治
- 宗教
- 意识形态

提供基础。

但第一版只需要实现最简单的：

```text
亲眼看到
被可信对象告知
被不可信对象告知
```

三种信息来源。

---

# 19. 成功标准重新定义

v0.3 不再以“每局发生很多事”为成功。

真正的成功需要同时满足以下几条。

## 19.1 因果一致性

事件真的改变世界。

不能：

```text
日志说发生了背叛
但库存、关系、位置都没变
```

---

## 19.2 路径依赖

过去的选择确实改变未来。

同一个 NPC：

```text
Day 1
和
Day 30
```

不应该像两个互相无关的实体。

---

## 19.3 认知差异

不同 NPC 对同一事件可以拥有不同认识。

但必须能追溯：

> 他为什么会知道 / 不知道 / 误解。

---

## 19.4 反事实可感知

玩家回顾时能够产生：

> “如果当时没有这样做，后面可能完全不同。”

这是戏剧性的重要来源。

---

## 19.5 历史分叉

同样初始规则、不同选择序列，应逐渐形成：

```text
不同关系
不同组织
不同资源分布
不同空间结构
```

而不仅是不同台词。

---

## 19.6 现实知识可迁移

玩家逐渐依靠：

- 判断人
- 判断利益
- 判断信息
- 判断信任
- 判断风险

而不是只靠背表。

---

## 19.7 观察价值

最强的一条验收标准仍然可以保持：

> **把世界自己运行一段时间后，我愿意停下来阅读它发生过什么。**

但现在增加一句：

> **而且我能够从中发现不止一种合理故事。**

---

# 20. 我们不追求什么

第一阶段明确不追求：

- AI 自动写精彩剧情
- 每分钟都发生冲突
- NPC 像人类一样拥有完整意识
- 所有人都高度聪明
- 文明自动出现
- 模拟真实历史
- 所有行为都调用模型
- 全体 NPC 都进行长链推理
- 自动保证“好玩”

我们追求的是：

> **一个最小、可验证的因果世界。**

---

# 21. Jev 与规则系统的具体分工

## 规则处理

```text
能不能做
需要多少资源
耗时多久
是否成功到达
物品如何变化
是否受伤
是否死亡
```

## Jev 判断

```text
我想做哪个允许动作
我要先响应谁
我愿不愿意帮助
我要不要继续合作
我现在更相信哪一种选择
```

## Belief System 处理

```text
我知道什么
我不知道什么
我以为什么
这个信息来自谁
我有多信任这个来源
```

## Observer System 处理

```text
哪些事件可能有关
哪些历史片段值得展示
不同人物如何描述同一事件
```

四者不能混合。

---

# 22. 第一个真正值得实现的技术切片

不需要先做整个营地。

先做四个人：

```text
A：有食物
B：没食物
C：目击者
D：后来才听说这件事
```

过程：

```text
B 向 A 借粮
↓
A 选择接受 / 拒绝
↓
真实世界改变
↓
C 亲眼看见
↓
D 通过 C 听说
↓
C 与 D 对事件的认知不同
↓
下一次 A / B / C / D 决策读取各自 Belief State
```

只要这一小段成立，我们就已经拥有：

- 真实事实
- 局部感知
- 信息传播
- 不同认知
- 选择
- 后果
- 历史
- 二次选择

这比“30 个 NPC 会自由聊天”更接近项目核心。

---

# 23. 第二个技术切片：允许误解制造真实后果

设计一个完全可控测试：

真实事件：

```text
A 拒绝 B 的请求，
原因是 A 自己也只剩最后一份食物。
```

C 只看到：

```text
A 拒绝 B。
```

C 不知道 A 的库存。

于是 C 可能形成：

```text
A 很自私
```

然后 C 后续减少与 A 合作。

如果：

```text
认知差异
→ 行为变化
→ 世界变化
```

真的跑通，

我们第一次获得：

> **认知制造现实**

这一层。

---

# 24. 第三个技术切片：历史而不是剧情

让 12 人营地运行 30 个游戏日。

不设置任何主线任务。

只放：

- 资源约束
- 关系
- 信息差
- 第二营地可能性
- 少量环境扰动

然后停止运行。

人工观察：

1. 有没有明显的事件链？
2. 能不能追溯到真实选择？
3. 是否存在关键分叉？
4. 是否出现不同人物对同一历史的不同解释？
5. 是否存在“如果当时……”的反事实感？
6. 是否愿意继续观察？

如果成立，再扩展。

---

# 25. 关于“社会算力”的正式定义

此前我们用过“社会算力”这个词。

v0.3 给它一个更准确的项目内定义：

> **社会算力 = 大量局部主体在有限信息、不同目标和不同认知条件下反复选择，并通过共享世界相互改变选择条件的总体计算过程。**

它不是：

```text
1000 个模型一起算最优答案
```

而更像：

```text
A 的选择改变 B 的条件
B 的选择改变 C 的认知
C 的选择改变资源
资源改变 D 的目标
D 的行动又反馈到 A
```

宏观结构不是一个中央模型算出来的。

它是循环产生的。

---

# 26. 将来的文明不应该“被生成”，而应该“被承载”

远期如果出现：

- 市场
- 家族
- 派系
- 规则
- 仪式
- 法律
- 宗教
- 国家

不能只是语言模型说：

> “他们建立了一个国家。”

必须有可执行结构。

例如“税收制度”至少意味着：

```text
谁有征收权
谁被征收
何时结算
什么资源被转移
拒绝会怎样
谁知道这条规则
谁承认它
谁不承认它
```

所以：

> **制度不是文本。制度是长期稳定的行为约束。**

只有这一层成立，文明才算真正进入模拟。

# 28. 开发过程中的红线

### 1. 不允许模型直接改世界状态

模型输出只能是意图。

---

### 2. 不允许 NPC 读取全局真相

NPC 只能依据自己的 Belief State。

---

### 3. 不为了戏剧性偷偷修改选择

戏剧性属于观察层。

---

### 4. 不把随机噪声叫作涌现

涌现必须能够追溯因果。

---

### 5. 不把文本描述当作制度

任何长期结构都必须落实到可执行规则。

---

### 6. 不把“模型很聪明”等同于“世界很活”

活着的感觉来自：

```text
持续性
+
后果
+
记忆
+
信息差
+
路径依赖
```

---

### 7. 不要求所有角色最优

错误、偏见、迟疑、短视都是世界的一部分。

# 29. 项目现在最核心的五个问题

## 问题一

> **一个由有限理性主体构成的世界，能否在没有主线脚本的情况下生成长期可解释的历史？**

## 问题二

> **不同主体对同一世界拥有不同认知时，这种认知差异能否稳定地产生社会结构，而不是随机噪声？**

## 问题三

> **过去的经历能否真正改变主体未来的判断方式，而不只是让日志越来越长？**

## 问题四

> **主体改变环境、环境再塑造主体的闭环，能否在长期运行中形成稳定但非预写的制度、习惯与群体结构？**

## 问题五

> **当玩家不再消费预写剧情，而是观察并介入一段真实运行的历史时，这种体验是否足够成为一种新的游戏乐趣？**

---

# 30. v0.4 的一句话定义

> **我们不是让 AI 替人类写故事。我们让大量有限主体不断选择，让选择改变世界，让世界保存历史，让历史反过来改变主体，再让观察者从这些痕迹中发现故事。**

进一步压缩成三句：

> **选择生成历史。**  
> **观察生成故事。**  
> **反馈塑造主体，主体反过来塑造世界。**

而 Jev 在其中只负责一件很小、但可能非常关键的事：

> **在每一次新的可能性展开之后，帮助某个局部主体完成下一次选择。**

---

# 31. 下一轮开发时直接使用的判断框架

每当准备增加一个新功能，先问五个问题：

```text
1. 它增加了什么新的可能性？
2. 谁能够知道它？
3. 它如何改变主体的选择？
4. 选择之后留下什么不可逆后果？
5. 玩家以后能否从这些后果中重新发现因果？
```

五个问题都回答不了的功能，

优先级降低。

因为它可能只是在增加内容，

而没有增加：

> **世界生成历史的能力。**

---

# 32. 从“知识编码”到“环境塑造”

这次关于企业垂直智能、FDE 与商业强化学习的讨论，为本项目补充了一个非常重要的设计视角。

传统知识工程倾向于：

```text
复杂经验
↓
访谈 / 总结
↓
显式规则
↓
Workflow
↓
系统执行
```

传统 NPC 设计实际上也采用同样路线：

```text
设计师观察“人会怎么做”
↓
把经验压缩为状态机 / 行为树
↓
IF / THEN
↓
NPC 执行
```

这种方式并非错误。

它特别适合：

- 物理规则
- UI 流程
- 资源校验
- 明确制度
- 可重复行为

问题在于：

> **一旦试图用显式规则完整编码复杂主体，压缩损失会迅速增大。**

因此项目采用新的分工原则：

### 规则负责约束世界

```text
什么允许发生？
需要付出什么成本？
结果如何结算？
```

### Agent 负责在约束内判断

```text
我现在想做什么？
我相信什么？
我愿意承担什么风险？
```

### 环境负责给予真实反馈

```text
你的判断到底造成了什么？
```

这意味着，开发工作的核心逐渐从：

> **“把聪明写进 NPC。”**

转向：

> **“把反馈写进世界。”**

---

# 33. WorldCore 才是整个项目最重要的基础设施

如果模型说：

> “冬天快到了，我准备囤粮。”

但游戏实际上没有：

- 季节影响
- 库存
- 食物消耗
- 价格变化
- 稀缺后果

那么 NPC 只是在“表演聪明”。

世界没有活起来。

真正有效的系统必须是：

```text
冬季到来
↓
捕鱼效率下降
↓
食物供给减少
↓
库存开始下降
↓
价格 / 交换条件变化
↓
不同 Agent 采取不同策略
↓
策略真实影响其他人的生存条件
```

因此：

# **模型负责提出行为，WorldCore 负责让行为有重量。**

模型能力升级可以替换。

WorldCore 的因果一致性不能被替换。

---

# 34. 稳定层与液态层

“所有东西都液态化”不是本项目采用的假设。

完全液态的系统不会产生生命感，只会产生噪声。

本项目采用三层稳定性：

```text
┌──────────────────────────────┐
│ Liquid Layer                 │
│ 判断 / 策略 / 关系解释 / 组合  │
└──────────────↑───────────────┘

┌──────────────────────────────┐
│ Semi-Stable Layer            │
│ 身份 / 习惯 / 制度 / 组织 / 角色│
└──────────────↑───────────────┘

┌──────────────────────────────┐
│ Hard Layer                   │
│ 物理 / 资源 / 时间 / 空间 / 生死│
└──────────────────────────────┘
```

### Hard Layer

高确定性。

例如：

- 一份粮食不能被两个人同时吃掉
- 死亡必须有明确状态
- 地理距离真实存在
- 生产需要时间和资源

### Semi-Stable Layer

可以变化，但变化需要历史。

例如：

- 家族
- 商会
- 领袖
- 法律
- 身份
- 社会习惯
- 长期关系

### Liquid Layer

允许快速适应。

例如：

- 当前判断
- 当前计划
- 谈判策略
- 临时联盟
- 对风险的解释

项目的目标不是“消灭固态结构”，而是：

> **让适合稳定的东西稳定，让适合适应的东西适应。**

---

# 35. 智能不等于模型权重

本项目明确拒绝一种过度简化：

> “只要把足够多经验蒸馏进权重，NPC 就拥有完整人生。”

模型权重本身同样是一种压缩。

因此一个长期主体的“智能状态”应被理解为组合体：

```text
Policy / Model
+
Belief State
+
Memory
+
Social Graph
+
Skills
+
Tools
+
Commitments
+
World Access
+
Current Context
```

可以抽象为：

\[
AgentIntelligence
=
f(W, B, M, R, K, T, C, E)
\]

其中：

- \(W\)：模型 / policy
- \(B\)：belief
- \(M\)：memory
- \(R\)：relationships
- \(K\)：skills
- \(T\)：tools
- \(C\)：current context
- \(E\)：environment access

这意味着：

> **NPC 成长首先不需要重新训练 Jev。**

我们可以先通过外部状态，让“同一个基础模型”在十年后成为完全不同的人。

只有当这些机制不足以承载长期学习时，才考虑：

- adapter
- fine-tuning
- distillation
- online RL

---

# 36. 主体成长：从“记住经历”到“改变策略”

一个 NPC 只是不断积累 Memory，还不能叫成长。

真正的成长至少需要四个层次：

## Level 1：事实记忆

```text
A 曾经拒绝帮助我。
```

## Level 2：信念更新

```text
我开始降低对 A 的信任。
```

## Level 3：策略形成

```text
下一次缺粮时，我优先向 B 求助。
```

## Level 4：习惯 / 性格漂移

长期多次经历以后：

```text
我越来越不愿依赖别人。
```

于是：

\[
Experience
\rightarrow
Belief
\rightarrow
Policy
\rightarrow
Habit
\]

真正的长期角色应该允许：

> **经历改变“以后如何选择”。**

而不仅是改变“以后会说什么”。

---

# 37. 世界与主体的共同演化（Co-evolution）

假设两个初始参数几乎相同的 NPC：

\[
A_0 \approx B_0
\]

A 长期生活在：

```text
资源丰富
信任稳定
合作回报高
```

B 长期生活在：

```text
饥荒
背叛
暴力
合作经常被惩罚
```

运行足够长时间后：

\[
A_t \neq B_t
\]

随后：

```text
A 的行为
→ 强化合作环境

B 的行为
→ 强化防御 / 掠夺环境
```

于是产生：

```text
环境塑造主体
↓
主体改变环境
↓
新环境再次塑造主体
```

这不是单向 AI 决策系统。

而是：

# **Co-evolving Causal World**
## 共同演化的因果世界

远期的“文化”与“文明”，应该来自这种循环，而不是模型直接写出一段文明简介。

---

# 38. 社会算力：从比喻变成系统定义

项目内正式定义：

> **社会算力，是大量有限主体在不完全信息、不同目标、不同历史与不同认知条件下反复选择，并通过共享世界持续改变彼此后续选择条件的总体计算过程。**

它不是：

```text
1000 个 Agent 一起求全局最优
```

而是：

```text
A 的行动
↓
改变 B 的资源

B 的判断
↓
改变 C 的认知

C 的行动
↓
改变某个组织

组织规则
↓
改变 D 的选择成本

D 的行动
↓
重新改变 A 的世界
```

宏观结构不是中央模型输出。

它是：

\[
MacroStructure
=
Emergence(LocalChoices, SharedWorld, Feedback, Time)
\]

这里的关键变量不是单纯的“Agent 数量”。

而是：

- 反馈真实性
- 资源耦合
- 信息不对称
- 历史持续性
- 后果不可逆性
- 主体适应能力

---

# 39. “每一次服务都变成训练数据”在游戏里的对应物

企业智能讨论中有一个有价值的结构：

> 每一次真实业务行为，不应该只是完成任务，而应该成为下一次决策的学习信号。

在本项目中可以翻译为：

```text
每一次行动
↓
产生世界结果
↓
形成历史记录
↓
更新主体认知
↓
影响下一次选择
```

因此每个事件除了 `world_changes` 之外，未来还应该允许：

```yaml
learning_signals:
  belief_updates:
  trust_updates:
  skill_updates:
  habit_updates:
  goal_updates:
```

但必须保持一个原则：

> **学习信号来自真实后果，而不是编剧为了塑造人物手工指定结果。**

---

# 40. 不要过早做“在线强化学习”

“主体会学习”不等于第一版就应该做在线 RL。

第一阶段禁止把技术复杂度误认为世界深度。

优先级应该是：

### P0

```text
状态真的变化
```

### P1

```text
Agent 真正看到不同信息
```

### P2

```text
经历真正改变 Belief / Relationship
```

### P3

```text
过去经历真正改变未来行动
```

### P4

```text
群体互动真正改变环境结构
```

只有上述机制跑通以后，才判断是否需要：

```text
Policy Adaptation
↓
Parameter Update
↓
Fine-tuning / RL
```

否则很可能得到：

> 一个训练技术复杂，但世界依然空洞的系统。

---

# 41. Environment Designer：设计者的第二重身份

v0.3 把设计者定义为：

> **Choice-Space Engineer**

v0.4 再增加第二重身份：

# **Environment Designer**

Choice-Space Engineer 负责：

```text
主体能选择什么？
```

Environment Designer 负责：

```text
选择之后，世界如何诚实地回应？
```

两者组合：

```text
Choice Space
+
Consequence System
=
Meaningful Agency
```

如果只有 Choice Space：

> 玩家拥有大量按钮，但按钮没有真正重量。

如果只有 Consequence System：

> 世界很真实，但主体没有足够行动空间。

两者同时成立，才可能产生我们想要的：

> **有重量的自由。**

# 42. 从“内容量”转向“历史生成能力”

以后评估新功能时，不再优先问：

> 这个功能增加了多少内容？

而问：

> **它增加了多少新的历史生成能力？**

例如：

### 增加 1000 句 NPC 台词

可能增加内容。

但未必增加历史生成能力。

### 增加“借债与偿还”机制

只有几个动作。

但它可以产生：

- 信任
- 违约
- 债务
- 人情
- 报复
- 合作
- 继承

它的“历史乘数”很高。

因此可以定义一个粗略内部指标：

\[
HistoricalLeverage
=
NewChoices
\times
Consequences
\times
Persistence
\times
CrossAgentEffects
\]

优先做高 Historical Leverage 的系统。

# 43. v0.4 的最小 Demo 再升级

四人借粮切片继续保留，但增加“主体改变”。

初始：

```text
A：有 2 份粮
B：没有粮
C：现场目击
D：只通过 C 得知事件
```

## Round 1

```text
B 向 A 借粮
↓
A 拒绝
↓
C 目击
↓
D 从 C 得知
```

## Round 2

不同认知产生：

```text
B：
“A 不值得信任”

C：
“A 可能比较自私”

D：
“我听说 A 拒绝救 B”
```

注意：

三者并不完全相同。

## Round 3

环境出现第二次资源压力。

此时：

```text
B 不再向 A 求助
C 降低与 A 合作优先级
D 可能传播这个声誉
```

如果这些变化进一步导致：

```text
A 获得更少合作
↓
A 自己未来更缺资源
↓
A 变得更加防御
```

我们就第一次跑通：

```text
行为
→ 认知
→ 社会反馈
→ 环境变化
→ 主体策略变化
```

这就是 v0.4 的真正最小闭环。

# 44. v0.4 世界公理

目前项目可以暂定九条公理：

### 公理 1：世界先于故事

世界运行，不负责表演剧情。

### 公理 2：选择生成历史

未被选择的路径成为反事实。

### 公理 3：观察生成故事

故事是对历史的因果压缩。

### 公理 4：主体只对自己的世界模型行动

Belief State 不等于 World State。

### 公理 5：后果必须由世界结算

模型不能凭语言改变事实。

### 公理 6：历史必须产生路径依赖

过去必须真实限制或改变未来。

### 公理 7：反馈塑造主体

经历必须有机会改变未来的选择策略。

### 公理 8：主体反过来塑造环境

社会结构必须由持续行动维持，而不是由文本声明存在。

### 公理 9：稳定与变化必须分层

不是所有东西都应该随机，也不是所有东西都应该固定。

# 45. v0.4 的项目公式

现在可以把整个项目压缩成：

\[
Possibility
\rightarrow
Choice
\rightarrow
Consequence
\rightarrow
History
\]

同时：

\[
History
\rightarrow
Observation
\rightarrow
Story
\]

以及：

\[
History
\rightarrow
AgentAdaptation
\rightarrow
NewChoice
\]

最终形成：

```text
        ┌──────── Observation ────────→ Story
        │
World → Agent → Choice → Consequence → History
  ↑        ↑                         │
  │        └──── Agent Adaptation ←──┘
  │
  └──────── World Transformation ←───
```

因此项目真正的闭环不是“AI → 内容”。

而是：

# **世界 → 主体 → 选择 → 后果 → 历史 → 适应 → 新世界**

玩家进入的，是这条循环本身。
