## 1. 玩家必须看见哪些变化

| 编号 | 表现需求 | 可复用或最低占位方案 | 正式验收看什么 |
|---|---|---|---|
| A01 | 货物在谁身上、到哪里去了 | 现有背包/篮筐/资源堆，临时基础形状 | 发货、携带、放下与交付不重影、不复制 |
| A02 | 哪个储物点属于个人或公共仓库 | 同一容器加标识和权限提示 | 标识来源真实，不把未获知的私人库存展示给玩家 |
| A03 | 运输队真实移动 | 复用移动动画，必要时增加携物挂点 | 货物随保管人移动，路线与世界位置一致 |
| A04 | 警告、等待、撤退和护送 | 已有姿态/转向、短音效与图标 | 正常镜头下能理解当前动作，不靠长篇字幕 |
| A05 | 伤员搬运和照料 | 复用救援动作或明确标记的占位表现 | 被搬者位置、伤势和搬运者状态一致 |
| A06 | 地方与团体可被识别 | 简单旗号、营地标记、不同图案 | 已知标记能帮助识别，未知标记不自动泄露组织全名 |
| A07 | 集体商议与人物回应 | 聚集位置、朝向、发言标记、简短回应 | 看得出谁提议、谁回应，不能全员同帧读心 |
| A08 | 领导授权改变 | 公共岗位标识、仓库操作提示、成员称呼 | 职位变化可见；不把旧首领模型删除或换成敌人 |
| A09 | 运输损失与战斗痕迹 | 地面货物、损坏容器、已有血迹/尸体 | 与真实事件对齐，可在之后回访发现 |
| A10 | 交易交付与修复履行 | 简单交接动作或物资转移反馈 | 确认反馈发生在结算后，不预演未完成结果 |

图标、文字和位置关系可以先承担表现，不要求每个社会动作都有独立动画。占位可用不等于最终视觉验收通过。

## 2. 界面需求不是全知社会地图

第一版需要小型的交易条款、任务回应、个人承诺、职位权限和近期消息界面。优先显示玩家当下能做的事、知道的条件以及未证实之处。

不默认增加全图关系图、全体成员秘密立场、精确忠诚排序或未来战争预测。后台调试界面可读取更多状态，但必须有清晰模式标记且不混入正常存档体验。

颜色之外同时使用图案、位置或文字区分货物与标记。不能只有红绿颜色才能看懂谁在等货或哪笔交易失败。

## 3. 角色与身份表现

营地位置、部落归属、家族身份和派系不能用一个统一颜色强行表达。第一版的角色衣服可以相同，通过玩家已知的姓名、公开标记和现场行为辨认。

同一个 NPC 换了职位仍是同一个人。失位玩家保留模型、装备与已拥有物品；卸下职位徽记不能顺带清空其背包。

需要表现秘密派系时，不能为了让玩家“看到系统有效”自动给成员换统一制服。发现派系主要依赖共同活动与公开信息。

## 4. 许可与供应链边界

本轮新增第三方素材沿用当前执行基线的 CC0 准入要求。先查现有获准资产；缺失时才提出精确候选。未经用户规定的 vendoring 准入确认，不下载并正式纳入项目，不用“免费可下载”替代许可证据。

记录内容：来源 URL、包名、作者、许可文本或证据、版本/下载时间、原始 SHA256、文件格式、修改记录、衍生文件哈希、骨骼、动画名称、比例、材质、碰撞、Godot 导入结果及对应玩法需求 ID。

内部创建的占位资产标记 internal-placeholder，记录生成方式与源文件，不伪装成已审计的第三方 CC0 资产。

## 5. 验收状态必须分开

| 关卡 | 证据 | 不能替代什么 |
|---|---|---|
| 来源/许可已核实 | 精确包与许可证据、作者记录 | 不能证明引擎可用 |
| 准入已获确认 | 精确文件范围、哈希与确认记录 | 不能证明已复制或已导入 |
| 项目接入完成 | 受控路径、manifest、版本记录 | 不能证明画面正确 |
| Godot 导入通过 | 导入日志、骨骼/材质/动画检查 | 不能替代 GUI 实际观察 |
| 视觉验收通过 | 正常镜头下的截图/录像、识别结果 | 不能证明货物和状态正确 |
| 玩法验收通过 | 对应事件、库存、位置和原生路线 | 不能替代来源合法性记录 |

## 7. 本轮不增加的资产范围

不新增完整城堡、攻城器械、骑兵体系、不同文明全套建筑、数十套部落服饰、大规模群战动画、完整俘虏动画或世代幼体。先用少量资产证明真实运输、协作、救援、授权变化和失位后的连续生活。

新增需求必须对应一个实际可执行动作或可观察状态。没有规则支撑的战争过场、自动王冠切换、凭空出现的商队，不应作为“涌现系统已经完成”的展示材料。
