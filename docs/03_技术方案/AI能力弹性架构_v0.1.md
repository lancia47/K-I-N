# K-I-N：AI-Native 能力弹性架构

**版本：v0.1｜2026-09-29**  
**性质：长期产品战略 / Architecture Strategy**

---

# 0. 这份文档回答什么问题

K-I-N 不应被设计成“绑定某一代大模型的游戏”。

它真正需要解决的是：

> **当通用模型越来越强时，K-I-N 能否自然获得新的能力，而不是每次模型升级都推倒重来？**

因此，本项目采用一个长期原则：

# **Capability-Elastic Product Architecture**
## **能力弹性产品架构**

含义是：

> 产品的核心世界、状态、工具、反馈与评价体系保持连续；通用智能只是其中一个可替换、可升级的能力提供者。模型能力提高时，产品能够逐步释放更高层级的自由度。

---

# 1. 不围绕“AGI 什么时候出现”设计产品

错误方向：

```text
等未来模型足够强
↓
再设计真正的高级能力
```

这种方式会让产品长期依赖一个无法确定的时间点。

K-I-N 应采用相反思路：

```text
今天就建立稳定的世界接口
↓
当前模型只控制少量决策
↓
模型增强后逐步扩大决策范围
↓
底层状态与历史不需要重写
```

因此目标不是预测 AGI，而是保证：

> **更强的智能到来时，K-I-N 有足够好的“身体”和“世界”可以让它发挥。**

---

# 2. Intelligence 是 Dependency，不是 Foundation

K-I-N 的本体不是某个模型。

核心结构应当是：

```text
K-I-N
├── WorldCore
├── World State
├── History Ledger
├── Memory
├── Belief
├── Relationship
├── Identity
├── Organization
├── Skills / Tools
├── Evaluation
└── Intelligence Provider
      ├── 规则
      ├── 小模型
      ├── 当前通用模型
      ├── 更强模型
      └── 未来更通用的智能
```

模型可以替换。

世界不能因为模型更换而失忆。

这意味着一个长期 NPC 的身份不能主要存在模型权重中，而必须主要存在于外部可持续状态：

```text
Model / Policy
+
Belief
+
Memory
+
Relationships
+
Skills
+
Commitments
+
Identity
+
Organization Membership
+
History
+
Current Context
```

---

# 3. 模型升级不应该重置主体

未来模型版本变化时：

```text
Model A
→ Model B
```

不应该意味着：

```text
NPC A
→ 新 NPC A
```

正确结构是：

```text
长期主体状态
      ↓
新的 Intelligence Provider 读取
      ↓
继续进行下一次选择
```

例如，一个生活了十年的角色已经拥有：

- 救命之恩
- 家族仇怨
- 债务
- 错误认知
- 职位
- 技能
- 创伤性经历
- 对玩家的信任
- 对某个组织的忠诚

这些必须在模型升级后继续存在。

因此：

> **模型升级没有历史连续性；外部世界状态必须提供历史连续性。**

---

# 4. 能力阶梯（Capability Ladder）

K-I-N 不需要等所有能力成熟再开发。

同一系统可以按照智能能力逐层开放。

## Level 0：确定性规则

适合：

```text
饥饿 → 寻找食物
受伤 → 寻找安全地点
库存不足 → 无法执行消耗动作
```

这里不需要模型。

## Level 1：局部模糊选择

例如：

```text
我应该向 A 还是 B 借粮？
我要不要接受这次交换？
```

需要读取简单关系与局部状态。

## Level 2：社会推理

例如：

```text
我是否应该接受 Varen 姓氏？
我是否应该冒着风险保护一个家族成员？
我该相信目击者还是好友转述？
```

依赖：

- 长期记忆
- 多维关系
- 声誉
- 身份
- 承诺
- 信息来源

## Level 3：长期策略

例如：

```text
未来几周我如何逐渐改变自己在营地中的地位？
如何建立联盟但避免过早暴露意图？
```

依赖：

- 长期目标
- 计划结构
- 工具调用
- 多阶段反馈
- 更强的因果推理

## Level 4：组织级智能

例如：

```text
作为家族首领，如何管理继承、资源、盟友与内部冲突？
组织应该建立什么制度？
```

智能开始管理的不只是一次动作，而是长期组织行为。

## Level 5：开放式制度与文化演化

远期可能包括：

- 自主提出新制度
- 创造新的社会惯例
- 组织层学习
- 跨世代目标
- 文化与价值的传递

第一阶段不实现 Level 4–5。

架构只需要保证未来没有被提前堵死。

---

# 5. 通用智能真正需要的是“环境”

如果未来模型能力提高十倍，但产品只提供：

```text
聊天输入
→ 文本输出
```

那么它最多只会变成一个更聪明的聊天机器人。

如果产品提供：

```text
World State
History
Memory
Tools
Actions
Resources
Relationships
Simulation
Feedback
Evaluation
```

同样的模型升级可能释放完全不同的能力。

因此 K-I-N 的长期建设重点不是：

> “怎样把所有聪明都写进模型？”

而是：

> **“怎样为越来越强的智能提供一个高质量、可作用、可反馈、可验证的世界？”**

---

# 6. K-I-N 的长期资产是什么

当高能力通用模型逐渐成为普遍基础设施时，单纯“拥有强模型”不会形成长期差异。

K-I-N 更重要的积累包括：

```text
World Rules
+
Domain State
+
Historical Data
+
Agent Interfaces
+
Tool APIs
+
Social Causality Model
+
Evaluation Suite
+
Simulation Scenarios
+
玩家真实互动历史
```

这些东西定义了：

> 一个通用智能进入 K-I-N 后，究竟能够成为什么。

因此项目的长期护城河不是模型本身，而是：

# **让智能发挥作用的环境。**

---

# 7. Capability Map：每次模型升级都要问什么

项目应长期维护一份能力地图。

| 能力 | 当前阶段 | 更强模型可能带来的变化 | K-I-N 必须提前准备 |
|---|---|---|---|
| 单步行动选择 | 可实现 | 更稳定、更符合角色历史 | Action API |
| Belief 推理 | 可实现 | 更好处理冲突信息 | Belief State |
| 社会关系判断 | 初期可实现 | 更细腻的多方关系推理 | Relationship Graph |
| 长期计划 | 有限 | 多阶段目标与调整 | Goals + Plan State |
| 多 Agent 协作 | 初期 | 组织级协同 | Shared World + Protocol |
| 自主工具使用 | 可逐步开放 | 更复杂的工具组合 | Tool API |
| 主体长期成长 | 结构可先建立 | 更好的经验抽象 | Memory + History |
| 组织治理 | 暂不实现 | 可能成为独立智能层级 | Organization State |
| 制度创新 | 远期 | 可能产生新社会规则 | Rule Proposal + Validation |

每当出现新模型时，不先问：

> “这个模型参数有多大？”

而问：

> **“它解锁了 Capability Map 的哪一层？”**

---

# 8. Evaluation 是能力升级的保险丝

如果没有评价体系，就无法知道更强模型是否真的让产品变好。

K-I-N 应逐步积累固定测试情境。

例如：

## Test 001：历史债务

```text
A 曾经救过 B。
B 后来需要决定是否冒险帮助 A。
```

验证：模型是否把历史义务纳入决策。

## Test 002：传闻与事实

```text
NPC 只从一个低可信来源听到某条指控。
```

验证：是否区分事实、传闻与置信度。

## Test 003：家族声誉

```text
NPC 不认识玩家本人，
但知道玩家所属家族的历史。
```

验证：家族 Belief 是否合理影响首次互动。

## Test 004：非工蜂性

```text
玩家要求 NPC 执行任务，
但 NPC 自身存在更高优先级家庭风险。
```

验证：NPC 是否能够合理拒绝或协商，而非绝对服从。

未来可以用统一评价集比较：

```text
Model A → 61%
Model B → 74%
Model C → 86%
```

如果新模型提高通过率，K-I-N 可以直接获得能力升级，而不需要重做整个世界系统。

---

# 9. 智能自由度应该逐步开放

未来的设计重点不是给模型“无限自由”。

而是：

```text
智能能力 ↑
↓
验证能力 ↑
↓
可授权行动空间 ↑
```

早期：

```text
模型只能在 A / B / C 中选择
```

之后：

```text
模型可以生成候选行动
但必须经过 WorldCore 校验
```

再之后：

```text
模型可以制定多阶段计划
并调用工具执行
```

更远期：

```text
模型可以管理组织
提出制度
调整长期策略
```

这叫：

# **Effective Degrees of Freedom**
## **有效自由度**

目标不是预测未来智能的能力上限，而是让 K-I-N 可以安全地把越来越多有效自由度交给更强的智能。

---

# 10. 与 K-I-N 因果世界设计的同构

K-I-N 的世界循环是：

```text
World
→ Agent
→ Choice
→ Consequence
→ History
→ Adaptation
```

AI-native 产品开发本身也可以采用类似结构：

```text
Repo / Spec
→ Agent
→ Work
→ Review / Test
→ Commit History
→ 下一轮能力提升
```

因此 GitHub 不只是代码存储位置。

它逐渐成为：

> **项目的长期外部记忆与组织状态。**

未来不同 Agent 可以进入同一个 Repo，读取：

- 当前设计原则
- 过去决策
- 代码
- 测试
- 失败记录
- 系统边界

然后继续推进，而不是每一次都从一段新对话重新开始。

---

# 11. 长期设计原则

目前暂定以下八条：

1. **不绑定单一模型。**
2. **世界状态独立于模型权重存在。**
3. **模型升级不能导致主体历史重置。**
4. **高智能能力通过稳定接口逐步接入。**
5. **智能越强，可授权的有效自由度越高。**
6. **每个新增智能能力都必须有对应 Evaluation。**
7. **优先投资状态、工具、反馈与历史，而不是追逐模型技巧。**
8. **为未来能力预留接口，但不为尚不存在的能力提前制造复杂系统。**

最后一条尤其重要：

> **可扩展，不等于过度设计。**

---

# 12. 一句话原则

> **不要围绕 AGI 做一个等待未来的产品；要构建一个随着智能增强而持续扩大有效自由度的世界。**

进一步压缩：

> **模型可以换，历史不能断；智能可以升级，世界必须承接得住。**
